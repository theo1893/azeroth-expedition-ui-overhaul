# 设计与实现决策记录

本文件只保留会影响后续工作的稳定决策，不承担组件进度登记。当前阶段、文件
来源和下一步见
[`OVERHAUL_TRACKER.md`](implementation/OVERHAUL_TRACKER.md)。

## 项目目标

为 Turtle WoW `1.18.1` 制作一套美术统一的 UI overhaul，在保留香草魔兽厚重、史诗与手绘感的同时，解决 pfUI 过度现代化以及多个单体插件风格不统一的问题。

## 关键方向变化

1. 初期方案尝试了更现代的暗色奇幻、北欧厚重与《上古卷轴 5》综合色感。
2. 这些方向仍然过于现代，且逐渐接近《暗黑破坏神 3》式战斗框架，与香草魔兽差异过大。
3. 项目原则调整为“香草结构优先、材质增强次之”：尽量保留原始轮廓、布局、操作习惯和信息密度，只重绘材质与细节。
4. 大型龙头、尖冠、祭坛、精密细金线、持续发光和规则现代网格被列入统一禁止项。

## 聊天框

- 从平板式复古面板收敛为有真实页厚的“战地旧书”。
- 必须看到厚封皮、多层毛边书页、装订阴影、皮革频道索引签和直接落在纸面上的文字。
- 独立艺术资源 V3 与游戏内基准正式锁定。

## 任务模块

- 任务详情采用正式的双页“公会任务卷宗”。
- 任务追踪采用轻量的纵向“行军便笺”。
- 两者共享纸张、皮革、黄铜与磨损精度，但拥有不同物件身份和轮廓。

## 地图模块

- 大地图采用开阔的单张羊皮地图卷。
- 小地图采用双层旧黄铜航向罗盘。
- 曾尝试增加重型皮革背板和完整插件图标轨道，但导致大地图过重、小地图有效面积下降，因此整体回退并锁定 V1。
- 插件图标兼容属于运行时可选扩展，不能固化为永久按钮环。

## 角色属性模块

- 第一版横向双栏人物仪表板与香草 `C` 面板差异过大，弃用。
- 第二版恢复香草纸娃娃结构，但大型肖像章、右下龙饰、四个底部槽、宽紫色品质框和近黑人物背景仍未通过。
- 第三版移除越界装饰，恢复三个底部槽和近矩形轮廓，提亮人物底面并收窄品质色，最终以“香草同构角色面板 V1”锁定。

## 字体系统

- 不采用“全局单一古风字体”，而采用叙事标题、庄重标题和高密度系统信息三种职责。
- 霞鹜文楷 GB Medium 只负责旧书、卷宗、地图注释和短叙事标签，不能用于四十人团队、DPS、仇恨或长聊天正文。
- Noto Serif SC SemiBold 负责中文面板主标题和章节标题，用字重与材料框架增强庄重感。
- 英文标题、战斗数字和高密度正文优先引用客户端本地字体；Noto Sans SC Medium 只作为客户端中文字体不可用时的二级回退。
- 客户端字体不得复制进仓库。
- 仓库仅纳入静态 TTF。Noto Serif SC 与 Noto Sans SC 分别从官方可变 TTF 固定生成 `wght=600` 和 `wght=500` 静态实例，完整来源和生成记录保存在 `third-party/fonts/`。
- 三份字体目前是“实现基线”，不是“客户端兼容已通过”；必须完成 Turtle WoW `1.18.1` 实机测试后才能锁定为发布资源。

## 仓库清理

- 早期场景探索、被否决模块图、审计合成图和弃用提示词不再承担实现或验收职责。
- 原 `archive/` 的大型二进制已经移除，避免 Git 历史长期携带失败探索资源。
- 必要的弃用原因已经收敛到本文件与对应模块规范；后续不得重新建立仓库内过程图归档。
- 新的临时生成图、色键 raw 和可再生预览应保存在被 Git 忽略的
  `generated/`；确认后的透明生产母版进入 `assets/source/`，明确锁定的
  整体基准才进入 `assets/locked/`。

## 文档信息架构

- 项目说明统一集中在 `docs/`，由 `docs/README.md` 提供职责索引，
  `docs/WORKFLOW.md` 规定变更时的同步范围。
- `addon/` 只保存客户端运行文件、媒体和必须随包分发的许可证，不再放置
  README、上游说明或媒体清单。
- 根目录入口、Codex 自动发现文件、版本化执行提示词、固定 imagegen 技能和
  第三方来源／许可凭据因工具或分发约束保留在原位置，不视为散落的项目说明。
- `OVERHAUL_TRACKER.md` 是进度唯一事实来源；其他文档不得维护重复阶段表。

## pfUI 与代码架构

- pfUI 是功能、数据和生命周期底座，不是不可改变的视觉模板。
- pfUI `8.1.0` 已从只读参考迁移为 `addon/pfUI/` 项目维护分支；它和
  `addon/AzerothExpeditionUI/` 一起组成测试包。
- 允许直接修改 pfUI 的公共绘制入口、布局和呈现连接，但非视觉功能保持上游
  行为；每项 fork 差异必须记录来源文件和修改理由。
- 重构分为 `skin`、`adapter`、`replacement` 与 `extension`，每个组件在
  tracker 中登记采用方式。
- 复制或实质改写 pfUI 代码时保留 MIT 许可和来源记录。

## pfUI 全局视觉基线

- 尚未拥有组件级 runtime 的游戏界面先回退香草／Turtle WoW 原生呈现，
  不再加载 pfUI 的现代动作条、单位框、小地图、背包或 Blizzard skin。
- `/pfui`、解锁、分享等必须保留的维护表面使用不透明旧皮革／黄铜过渡
  基线；显式恢复 pfUI 可见模块时也使用该公共基线。
- pfUI 原本的半透明黑色方块和单像素现代边框不再作为默认视觉。
- 平面第三方状态条纹理与成对狮鹫配置仍保留为兼容过渡基线；默认回退时由
  原生状态条和原生双头狮鹫直接呈现。
- 公会、背包空间、耐久、好友、延迟、时钟、金币和区域等 legacy 信息
  widget 源码继续保留，但默认不加载呈现模块，也不挂载为聊天框或小地图
  下方的常驻 panel。

## 组件与资产粒度

- 整张效果图只用于视觉锁定，不可直接充当包含多个交互对象的 runtime 背景。
- 每个按钮、Tab、输入状态、滚动条、状态条和图标槽必须按游戏内逻辑对象拆分。
- 多个逻辑切片可以共用图集，但必须有 manifest／UV 和对象映射。
- 源资产、原始提示词、runtime 路径与验收阶段统一登记到 overhaul tracker，
  并与相关变更放在同一 Git 提交中。

## 生图执行器

- 所有生成和修图固定使用仓库内 `imagegen-0-143-0`，对应
  `@openai/codex@0.143.0`。
- 用户自然语言先依据基线和组件合同重写为版本化专业提示词；用户确认后，
  执行时把该正文原样传给技能。
- 不使用会话内建 imagegen，也不在没有新版本文件的情况下覆盖已执行提示词。

## 当前边界

已锁定的是美术与结构基准，不等于已经完成运行时切片、Lua/XML 实现、不同缩放测试或插件兼容验证。所有未锁定模块仍需继续走“香草原型截图 → 顶层结构 → 独立资源 → 游戏内场景 → 复审锁定”的流程。
