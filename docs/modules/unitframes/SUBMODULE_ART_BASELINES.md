# Unit Frames 子模块美术基线 Prompt

以下条款全部继承 [Unit Frames 主模块 Prompt](ART_BASELINE.md) 与
[全局 Prompt](../../GLOBAL_ART_BASELINE.md)。下列方向已由用户在
`UF-PRIMARY-SIM-V1` 与 `UF-PRIMARY-V3-SIM-V1` 中确认；它们是正式生产的
冻结可见约束，但不是 P4 source 接受记录。只有具体生产候选再次获得用户明确
接受后，才能凝结为锁定资产条款。

## `UF.PLAYER.SHELL`

绘制一个无文字、无图标、真透明的横向行军身份牌外壳。主体是深胡桃旧皮革，
左端有一块略歪的短黄铜夹片与两针粗修补线，右端只保留磨损皮革和一枚不居中
铆钉。皮革应像旧马鞍带、盾牌背带或帐篷捆扎皮被远征队拆下重用：裁边略钝、
厚薄不匀、染色和烟熏不均、只有少量可信的野外修补，不能像家具包边或工业
皮具。上下边低频起伏且不平行，但不得侵入 `200×25` 生命与 `200×4` Power
动态区。生产时生成一张完整外壳，不生成端帽 atlas；透明母版归一化为
`1284×252`，再确定性导出完整 `214×42` runtime。身份细节集中在两端，中央
长轨安静，未来三切片边界不得承载唯一识别特征。

## `UF.TARGET.SHELL`

与玩家框属于同一材料家族，但从零绘制而非镜像。右端有更明显的断裂黄铜
压片，左端仅有被磨亮的皮革折边；磨损与缝线位置和玩家框不同。不得烘焙
敌对色、等级、精英冠饰或目标类型。生产时单独生成一张完整外壳；不得与
Player 放进同一 production atlas，也不得镜像或复制 Player 像素。右端身份
不得扩散成长轨上的连续花纹，未来三切片边界不得承载唯一识别特征。透明母版
归一化为 `1284×252`，再确定性导出完整 `214×42` runtime。

## `UF.TARGETTARGET.SHELL`

绘制紧凑的 `112×34` 身份条：更薄的旧皮革、少量烟褐内衬和两至三处短促
氧化黄铜痕迹。保留粗厚可读轮廓，但删去大框的大部分装饰；不能变成规则小
卡片或把大框直接等比缩小。

## `UF.FOCUS.SHELL`

绘制紧凑的 `112×39` 追踪身份条。主体与目标的目标同族，但一段褪色靛蓝
猎踪布结从右上皮革夹层露出，布结必须被皮革与一枚暗铜钉真实压住。它是唯一
焦点识别元素，面积克制，不侵入动态文字与条形区；不得使用宝石、符文环、
蜡封或蓝色常亮描边。

## `UF.BAR.HEALTH.FILL`／`UF.BAR.POWER.FILL`

生成两条无色灰阶、完全不含文字和状态色的哑光颜料纹。Health 比 Power 略
粗，像矿物颜料被粗刷在烟褐底层上；Power 更窄、更密、更克制。均只允许
低频横向刷痕、少量不等宽色料堆积和短促暗部，不能出现居中亮点、重复斜纹、
镜面高光、渐变玻璃、皮革纹、金属纹或透明缺口。灰阶明度要足以承受 pfUI 的
`SetStatusBarColor` 乘色；Mana、Rage、Focus、Energy 等语义色全部由运行时
提供。最终分别导出为 `64×32` 与 `64×16`。

`UF-B1 V2 final.r2` attempt 3 已于 `2026-08-11` 被用户接受为该子模块的
像素 source：Health SHA-256 `8d19ffe9…08e1f`，Power SHA-256
`0668eddb…87f1`。Health 必须保持更粗、更深的矿物刷痕，Power 必须保持更窄、
更静的颜料起伏；二者继续由 pfUI 运行时乘经典语义色。后续导出不得添加现代
玻璃光、中心热点、规则斜纹、端帽、外框或任何 A／B 失败外壳元素。

## `UF.STATE.HOVER.RIM`／`UF.STATE.AGGRO.RIM`

不单独进行 ImageGen。由每张用户接受外壳的 Alpha 和边缘色确定性派生：Hover
只在两三段高磨损边出现低 Alpha 暖白响应；Aggro 只在两端和一小段下缘出现
暗红／橙褐响应。不得形成整框连续光圈，派生纹理不得覆盖动态内容或接管鼠标。

## `UF.RAID.MEMBER.SHELL.A-D`

把主模块“远征队行军身份牌”转译为 40 个高密度点名名条：每个成员只用一圈
轻薄、手裁不完全平直的深胡桃旧皮革夹边和烟褐内衬，不制作缩小书页、厚卡片
或主单位框的等比副本。四个完整变体保持相同重量和安全区，只在低频缺口、
短补针、偏心暗铆钉及局部暗铜修补上不同；按 `pfRaid` 槽位确定性分布，避免
40 个完全相同的工业重复。

标准 art box `74×37`，真实 `70×33` Secure Button 内缩 `2px`；外夹边在
100% 尺寸只露出约 `2px`。粗犷感必须由 40 个名条形成的整组烟褐编队、低频
轮廓误差和少量真实修补共同产生，不能靠加粗每个框、连续金线、均匀毛孔、
等距针脚、圆角卡片或透明黑玻璃。不得增加覆盖整团的共享书框、金属框或底板。
不得烘焙名称、血量、职业色、状态、Aura、Raid Icon 或任何点击反馈。

`UF-RAID-A2` 冻结为“模型供材、Python 造壳”：未来 ImageGen 只画四块无物件
轮廓的连续材料 donor——深胡桃旧生皮、烟褐静内衬、暗哑氧化黄铜和烟黑粗麻
线材质。donor 不得出现框体、端帽、开口、补丁、针脚、铆钉、维修布局、标签
或任何动态内容；不得把 Chat 的书本几何带入团队框。模型只负责早期 WoW 的
宽块手绘尺度、材料厚度、左上暖光、低频烟熏磨损与克制的综合色差。

最终四张完整外壳的轮廓、Alpha、内衬、接触阴影、三切片安全区和维修差异均
由确定性 builder 构造。A 为左上浅缺口加右下两条不等缝补；B 为右侧偏心暗
铆钉加右下克制磨痕；C 为左侧短皮补丁加两处乱线且无金属；D 为右侧歪斜小
暗铜片加左下微裂。维修必须完全留在固定 `48px` source 端部，中央名称区和
伸缩区安静。Python 可以裁取、cover-fit、mask、低频乘光、清透明 RGB、缩放
与三切片；不得生成新笔触、修复 donor 美术、复用 A1 失败像素或改变动态层级。

接受像素基线为 `UF-RAID-A2-DONOR V1 attempt 5` 的四个固定 `512×288` sample
window，经 builder 形成的四张 `592×296 RGBA` source。唯一例外是忽略未消费
外围 field bbox 最大 `19px` 偏差；外围像素本身不属于视觉权威。runtime 固定为
四张独立 `74×37` TGA，标准宽度使用完整纹理，其他宽度只允许从同一变体做
`6/62/6` 横向三切片；不得重绘、镜像、跨变体拼像素或纵向拉伸。

## `UF.RAID.STATE.RIM`／`UF.RAID.STATE.PIP`／`UF.RAID.AURA.RIM`

Raid 的 Hover／Aggro 不单独生图：从每个接受外壳的 Alpha 确定性派生两三段
断续边缘，分别运行时乘暖白或暗红／橙褐色，替代 pfUI 当前完整矩形 `glow2`。
Combat／Aggro 角标使用小型撕裂颜料记号；Aura 只增加一像素烟黑承托。状态
判定、透明度、图标本体、冷却、层数和 Tooltip 全部继续由 pfUI 提供。禁止
整框霓虹、常亮白框、现代发光卡片和把状态直接画进成员外壳。

## `UF.RAID.GROUP.LABEL.BACKING`

若未来启用 `raidgrouplabel`，在既有动态 `Group N` FontString 后放一条克制的
旧布／薄皮点名签；只容纳文字，不形成小队外框。当前 profile 为关闭状态，
因此只登记方向，不进入本批正式生产。
