# 后续实现路线

## 阶段 0：确认运行环境

- 记录 Turtle WoW `1.18.1` 实际客户端构建与可用 Lua/XML API。
- 列出当前 pfUI 与单体插件清单、加载顺序、SavedVariables 和相互依赖。
- 确认要采取“独立整合插件”“pfUI 主题层”还是两者结合。
- 在开始替换贴图前建立可随时关闭的兼容层，避免破坏原插件功能。

## 阶段 1：公共设计令牌

建立统一的：

- 颜色：羊皮、深皮革、胡桃木、氧化黄铜、黑铁、状态色。
- 字体：标题、正文、数字、战斗提示与中文回退。
- 尺寸：边框厚度、页签高度、按钮尺寸、槽位尺寸与安全区。
- 状态：默认、悬停、按下、选中、禁用、警告、危险、离线、死亡与超出距离。
- 光照：左上暖光、短促金属高光和统一磨损尺度。

公共令牌应先写成文档和常量表，再生成各模块资源。

字体基线已经整理到 [`FONT_SYSTEM.md`](FONT_SYSTEM.md)。开始编写模块代码前，必须先验证其中三份静态 TTF 能否由目标客户端从插件目录稳定加载；验证失败时按文档规定回退到客户端字体，而不是替换全局 `Fonts` 目录。

## 阶段 2：资源生产管线

- 为每个锁定模块制作无文字高分辨率母版。
- 将中央填充、四边、四角、装饰件和交互覆盖层分开。
- 优先使用九宫格、平铺纹理和独立角件，避免拉伸毛边、书脊与金属端帽。
- 保存可编辑源文件到 `source-assets/`。
- 将运行时贴图导出到 `addon/AzerothExpeditionUI/Media/`。
- 建立尺寸、透明边缘、重复纹理、色域与命名校验工具。

## 阶段 3：先实现已锁定模块

建议顺序：

1. 聊天框：可验证九宫格、字体、滚动与输入状态。
2. 任务追踪：可验证纵向扩展、任务状态和战斗中可读性。
3. 任务详情：验证双页布局、任务目录和正文安全区。
4. 小地图：验证遮罩、方向件、缩放、追踪和插件图标兼容。
5. 大地图：验证原始地图图层保留与外围卷轴资源。
6. 角色属性面板：验证纸娃娃、装备槽、Tooltip 和插件附页。

每完成一个模块，都需要在 `1920×1080`、常见 4:3、16:9 与超宽屏下检查 UI Scale。

## 阶段 4：继续锁定战斗核心

下一批优先设计：

- 保留双头狮鹫识别的动作条。
- 玩家、目标、小队与四十人团队框架。
- DPS、治疗、承伤与仇恨监控。
- 消耗品、关键增益、减益与冷却监控。
- 姓名板、施法条与首领警报。

这些组件必须优先保证战斗可读性，装饰面积和纹理复杂度低于非战斗窗口。

## 阶段 5：测试与发布

- 验证战斗锁定、重载 UI、角色切换、分辨率切换和插件缺失状态。
- 检查中文、英文、数字、百分比和长文本溢出。
- 检查静态 TTF 的首次加载、重载 UI、字体回退、缺字、内存占用和不同 UI Scale 下的小字号清晰度。
- 检查明亮雪地、昏暗洞穴与高饱和法术环境中的对比度。
- 记录所有支持、可选支持和明确不兼容的插件。
- 生成版本化发布目录，不直接发布 `source-assets/`。

## 完成定义

一个模块只有同时满足以下条件才算完成：

- 结构与锁定基准一致。
- 运行时交互完整。
- 可在目标分辨率和 UI Scale 下正常缩放。
- 不覆盖关键游戏信息。
- 与其他已实现模块在材料、字体、状态与光照上统一。
- 可以单独启用、禁用或回退到原插件皮肤。
