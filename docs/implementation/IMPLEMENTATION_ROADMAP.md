# 实现路线

具体进度不在本文重复维护；唯一状态事实来源是
[`OVERHAUL_TRACKER.md`](OVERHAUL_TRACKER.md)。

## 0. 基础与兼容层

- 记录 Turtle WoW `1.18.1` 客户端、Lua／XML API、pfUI 版本和加载顺序。
- 未达到组件级 runtime 门槛的可见 pfUI 模块先按依赖组回退原生 Frame，
  保留非呈现功能，并用实机测试确认客户端原生 UI 没有被误隐藏。
- 建立 `PfUIBridge`、`MediaRegistry` 与缺失对象的局部回退。
- 从聊天实现中提取九宫格、三段式、Button、Tab、StatusBar 和 IconSlot
  等已被真实模块使用的公共组件。
- 复制 pfUI 实现时保留 MIT 声明并记录上游文件与提交。

## 1. 组件合同与设计令牌

- 为颜色、字体、边框厚度、按钮状态、磨损尺度和光照建立公共令牌。
- 为每个模块记录真实 Frame／API、逻辑对象、交互状态、UI 尺寸、文字安全区、
  可拉伸区和回退条件。
- 整张视觉原型最多达到 `P2`；完成组件合同和生产提示词后才能进入 `P3`。

字体候选及回退见 [`FONT_SYSTEM.md`](FONT_SYSTEM.md)，资产流程见
[`../ASSET_PIPELINE.md`](../ASSET_PIPELINE.md)。

## 2. 已锁定模块

建议顺序：

1. 聊天 V3：先验证 atlas、状态切换、拖动和尺寸策略。
2. 任务详情：`QL-A1` 空卷宗结构母版已经确认并进入
   `assets/source/quests/ql-a1/`；`QL-A2 V1` 已因外置封脊、翻页与图层
   错误退回，`QL-A2 V2.1` 又因装订针脚偏离绝对中心线、针脚与两侧纸页
   交界突兀及正文纸面纹理过密而由用户退回。新的 `QL-A2 V3`
   production draft 保留八对象边界，但把物理双页固定为围绕
   `QuestLogFrame` 中线的近 1:1 结构，把 `GUTTER.STITCH` 改为无纵向绳杆的
   单个横向针脚站，并要求纸页内折在更高图层遮住针脚端点。用户授权 V3
   提示词后才可使用固定执行器重新生成；接受具体候选后才进入
   `assets/source/quests/ql-a2/` 并建立确定性 crop manifest。
3. 任务交互：按 `L` 打开的任务日志与 NPC `QuestFrame`／`GossipFrame`
   分开实现。任务日志先处理地区展开、任务行与追踪标记、两套滚动条子对象、
   操作按钮、正文安全区和只读奖励槽；NPC 对话已经按 Greeting／Detail／
   Progress／Reward、每个真实按钮和三类物品槽拆成独立合同，但在取得目标
   客户端尺寸和锁定“NPC 委托文书”视觉前继续原生回退。两者不得把交互件
   烘焙进同一张背景，也不启用 pfUI 现代 Quest Log／Gossip skin。
4. 小地图：验证遮罩、缩放、追踪和插件图标溢出。
5. 大地图：保留原始地图图层，只重构外围卷轴与交互。
6. 角色面板：保留香草纸娃娃结构，逐项实现装备槽、属性和页签。

游戏页面中的任务追踪由外部插件提供，暂不进入上述顺序。取得该插件源码后，
先登记顶层 Frame、任务行、目标行、更新生命周期、数据状态、移动／收起能力
和回退路径，再把现有“行军便笺”视觉参考重写成 provider 专属生产提示词。

## 3. 战斗核心

- 保留双头狮鹫辨识度的动作条、姿态栏、宠物栏与微菜单。
- 玩家、目标、小队和四十人团队框架。
- 姓名板、施法条、Buff／Debuff、冷却、计时器与首领提示。
- DPS／治疗／承伤、仇恨与消耗品监控。

战斗组件先保证信息、点击和性能；装饰集中在组框、端帽和标题，不覆盖成员格、
技能图标或状态条。

## 4. 系统窗口

- 背包、银行、拾取与掷骰。
- 法术书、天赋、专业与声望。
- 商人、拍卖、邮件、交易与社交。
- Tooltip、确认窗口、设置、战场和其他香草系统面板。

优先复用公共 Button、Tab、ScrollBar、ListRow、IconSlot 与金币组件，不为
每个窗口重新生成一套近似资产。

## 5. 验收与收口定义

一个组件只有同时满足以下条件才可标记 `P6`：

- 结构与锁定基准一致，逻辑对象没有被烘焙进背景。
- 运行时交互、回退和缺失依赖处理完整。
- 通过静态测试、至少三种尺寸预演和目标客户端实机测试。
- 中文、英文、数字和长文本不会越过安全区。
- 在明亮、昏暗和高饱和战斗环境中保持可读。
- tracker 同步记录源资产、原始提示词、runtime 路径和验证日期。

`P6` 后必须再执行一次 `P6-C` 仓库收口：

- 核对最终 prompt/source/manifest/exporter/runtime/实现/测试和实机证据。
- 生成精确保留／删除清单，排除共享依赖，并取得用户确认。
- 清除 raw、失败候选、预演、临时 atlas、过时 prompt、实验工具／参考和
  重复过程文档。
- 运行仓库契约、链接和相关 smoke test。
- 使用独立提交把 tracker 标记为 `P6-C`；只保留最终维护与再生所需内容。
