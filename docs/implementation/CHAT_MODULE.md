# 聊天模块实现说明

## 当前边界

聊天模块当前只接入 pfUI，不对其他聊天单体插件做兼容、换肤或定位：

| 职责 | 提供者 |
|---|---|
| 聊天窗口、Tab、停靠、滚动、历史、输入框和底栏 | pfUI |
| 旧书九宫格、正文安全区、Tab 状态、输入区和底栏换肤 | AzerothExpeditionUI |

本模块不覆盖 `ChatFrame_OnEvent`、`SetItemRef` 等聊天行为入口，也不修改
任何第三方插件文件。

## 0.3.1 pfUI-only 高精度基线

实机截图显示，旧版主书框只有 `512 × 293` 个有效像素，却会随 pfUI
窗口放大到约 `751 × 590`。同时单张贴图被同时拉伸宽高，造成纹理模糊、
包角变形和边框厚度不一致。

`0.3.1` 采用以下结构：

1. 主书框升级为 `1024 × 1024` 32 位 TGA，有效书框占顶部 586 像素。
2. Lua 使用同一张纹理的九组 UV 构成九宫格；四角保持尺寸，四边只沿
   单一方向伸缩，中央纸面单独填充。
3. Tab 普通、悬停、选中和未读状态分别处理，但沿用 pfUI 的原始页签几何。
4. pfUI 左底栏三个字段分别使用独立皮革段，输入框使用独立纸带。
5. Tab、底栏、输入条和蜡封资源以 2× 分辨率输出。
6. `FCF_SelectDockFrame` 与 `FCF_DockUpdate` 完成后立即刷新视觉状态；
   低频维护只更新贴图和颜色，不改变现有框体锚点、尺寸或父级。

## 加载与回退

`AzerothExpeditionUI.toc` 只声明 `pfUI` 为依赖。插件在 pfUI 完成建框后
应用视觉层，不等待或访问其他聊天插件。

禁用 `AzerothExpeditionUI` 并重载界面即可回到原 pfUI 外观。模块不写入
`pfUI_config`，只在模块应用阶段设置当前会话的最小尺寸和构图锚点，不在
周期维护中改写现有框体几何。

## 运行时资源

无文字母版通过项目指定的图像生成流程制作，随后由
`tools/build_chat_book_texture.py` 做确定性的外部黑底抠除、缩放与 TGA
转换。生成过程不把文字、频道名或消息烘焙进运行时纹理。

九宫格切线由构建脚本和 `Modules/Chat.lua` 共同锁定。预演文件
`ChatBookFrame_NineSlicePreview_v2.png` 使用实机截图的 751 × 590 尺寸，
用于在进游戏前检查边缘接缝、包角比例和纸面拉伸。

## 第一轮实机验收

1. 确认角色选择页启用 `pfUI` 与 `AzerothExpeditionUI`。
2. 进入世界后检查聊天框是否扩展到至少 440 × 320。
3. 检查聊天正文、输入框和 pfUI 底栏是否都能点击和滚动。
4. 连续切换所有聊天 Tab，确认没有原始页签位置闪现或二次跳位。
5. 进入 pfUI 解锁模式拖动左聊天框，确认书框同步移动且不产生 Lua 错误。
6. 将 pfUI 聊天框分别调整为宽、窄、高三种尺寸，确认四角不变形且边缘无接缝。
7. 当前客户端已确认不会出现 1024 纹理的纯绿占位；仍需在不同 UI Scale
   下确认边缘采样和显存占用。
8. 使用 `/aeui chat` 回退并确认重载后恢复原 pfUI 外观。

## 已否决的 imagegen-v4

imagegen-v4 不进入运行时，原因包括：

1. 风格过度规整，偏离前一版旧书、磨损和手工装订感。
2. 左右角件本身不对称，九宫格后顶部与底部无法共享稳定基线。
3. 主框内置了 Tab 分隔结构，与 pfUI 从左侧排列的真实 Tab 重叠。
4. 底部装饰与 pfUI 输入框、状态栏属于不同几何系统，无法靠缩放对齐。

反例仅保存在被 Git 忽略的
`generated/chat_pfui_hq/rejected_imagegen_v4/`，用于避免后续重复该方向，
不属于正式资源。

下一轮美术资源拆分、基线优先级和生成前验收条件见
[`CHAT_ART_RESOURCE_CONTRACT_V2.md`](./CHAT_ART_RESOURCE_CONTRACT_V2.md)。
