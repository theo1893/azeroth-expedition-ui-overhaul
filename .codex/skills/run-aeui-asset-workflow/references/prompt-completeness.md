# 生产执行正文完整性

固定执行器只接收执行正文和声明的图片输入，不读取仓库链接或 work 解释。
每个 production／`.rN` 正文都必须自包含；不设字数下限，形容词、历史和情绪
重复不能替代约束。

按歧义决定细节量：

- 单一对象／单一状态可以简短，但所有适用门禁必须明确；
- atlas、多状态、装配、重复／平铺和拉伸资产必须逐 cell／对象说明；
- 输入冲突或反复失败必须写明 inherit／ignore 职责和客观最终自检。

标记 `production-draft` 前，确认正文逐项覆盖全部适用内容：

1. 世界内物件身份、精确范围和不得退化成的对象。
2. 对象／状态数量、名称、顺序、runtime 所有权和禁止烘焙的动态内容。
3. 每张图片输入的权威、独立继承职责和明确忽略项。
4. Canvas、排布、cell 顺序、bounds、margin 和物件占用。
5. 视角、透视、方向、尺度、光照、z-order、接触和重叠。
6. 逐对象解剖、轮廓、材料、边缘、状态和相互关系。
7. 文字／图标安静区、crop、stretch、tile、repeat、seam 和 safe area。
8. 锁定美术 DNA：年代、笔触、配色、材料层级、磨损和具体反模式。
9. Alpha／色键、输出清洁度和其他技术约束。
10. 只重复最高风险客观门禁的简洁最终自检。

适用的硬门禁必须进入执行正文，不能只存在于组件合同或继承说明。权威已知时
使用精确数量、方向、职责和有界关系；执行必需值未知时返回组件合同，不得
编造。先解决矛盾再写正文。只有能消除一种有意义误解的条款才增加有效细节；
provenance 历史、commit ID 和过程叙述留在 work，除非它们会改变生成结果。
